## 2. 1일차: 로봇 구동 시스템과 임베디드 시스템

### 2.1 이론

#### 2.1.1 로봇 구동 시스템

1. 로봇 주행은 단순히 모터를 돌리는 것만으로는 되지 않는다. 
2. 센서 데이터 처리, 위치 추정, 경로 계획, 모터 제어가 **동시에** 수행되어야 하는데 각 기능이 요구하는 연산량과 제어 주기가 서로 다르다. 
3. 그래서 로봇 시스템은 역할을 **고수준(High Level)** 과 **저수준(Low Level)** 으로 나누어 구성한다.

#### 2.1.2 고수준과 저수준의 역할

**고수준 (High Level Decision Making)**

- 담당 장치: SBC (Single Board Computer)
- 대표 하드웨어: Jetson, Raspberry Pi
- 주요 기능: 상황 인식(Perception), Localization / Mapping / SLAM, Path Planning, Navigation
- 다루는 데이터: 카메라, LiDAR 등 대용량 센서 데이터
- 소프트웨어 환경: Linux + ROS2 (여러 노드 동시 실행)
- 요구 성능: 높은 연산 성능과 메모리

**저수준 (Low Level Control)**

- 담당 장치: MCU (Micro Controller Unit)
- 대표 하드웨어: Arduino, OpenCR, ESP32
- 주요 기능: 모터 PWM 출력, 엔코더 처리, PID 제어, 센서 데이터 수집·전처리
- 다루는 데이터: GPIO, ADC/DAC 등 하드웨어 신호
- 소프트웨어 환경: 펌웨어 또는 RTOS
- 요구 성능: 짧고 **일정한** 제어 주기

#### 2.1.3 왜 역할을 분리하는가

- 고수준 작업은 연산량이 많고 저수준 작업은 빠르고 일정한 주기가 중요하다. 요구사항이 서로 다르다.
- SBC는 리눅스 기반이라 다양한 소프트웨어와 고성능 연산을 제공하지만 여러 프로세스가 동시에 실행되어 **제어 주기가 흔들릴 수 있다.**
- MCU + RTOS는 모터 제어처럼 주기적인 작업을 안정적으로 수행한다.
- 따라서 역할을 나누면 각 하드웨어의 장점만 골라서 활용할 수 있다.

#### 2.1.4 임베디드 시스템

1. 임베디드 시스템은 **특정 기능을 수행하도록 설계된 시스템**으로 MCU를 기반으로 동작한다. 
2. 센서와 액추에이터에 직접 연결되어 물리적인 환경과 상호작용한다. 
3. 연산 능력과 자원은 제한적이지만 실시간 처리와 제어에는 적합하다. 

### 2.2 실습 수행 과정: LED 점멸 (Tinkercad)

1. Tinkercad Circuits에서 Arduino Uno R3와 브레드보드를 배치하고 5V와 GND를 브레드보드 전원 레일에 연결했다.
2. LED는 220옴 저항을 직렬로 달아 과전류를 막고, 애노드를 디지털 핀(D7)에, 캐소드를 GND에 연결했다.
3. 코드를 작성하고 시뮬레이션을 실행해 동작을 확인했다.

### 2.3 구현 결과 및 코드 분석

```cpp
const int ledPin = 7;
void setup() { pinMode(ledPin, OUTPUT); }
void loop() {
  digitalWrite(ledPin, HIGH); delay(1000);
  digitalWrite(ledPin, LOW);  delay(1000);
}
```

- **결과:** LED가 1초 간격으로 켜지고 꺼졌다(주기 2초).
- **적용 이론:** `pinMode`로 핀을 출력으로 설정하고 `digitalWrite`로 HIGH/LOW를 내보내는 가장 기본적인 GPIO 제어. `setup()`은 한 번, `loop()`는 무한 반복되는 아두이노 프로그램 구조를 사용했다.

처음에는 "로봇 자율주행"이라는 목표와 LED를 깜빡이는 실습이 잘 연결되지 않았다. 하지만 고수준/저수준 구조를 배우고 나니 아무리 좋은 경로 계획도 결국 MCU가 모터에 PWM을 정확히 내보내야 로봇이 움직인다는 것을 이해했다.
