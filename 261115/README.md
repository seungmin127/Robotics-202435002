## 2. 2일차: 입출력 기초와 PWM

### 2.1 이론

#### 2.1.1 플로팅(Floating) 전압

입력 핀이 어디에도 확실히 연결되어 있지 않으면 전압이 HIGH도 LOW도 아닌 떠 있는 상태가 된다. 이때는 주변 노이즈나 손의 정전기에도 값이 바뀌어 버튼을 누르지 않았는데도 입력이 제멋대로 읽힌다.

#### 2.1.2 풀다운(Pull-down) 저항

플로팅을 막기 위해 입력 핀과 GND 사이에 저항을 연결한다. 버튼이 떼어져 있을 때는 저항을 통해 핀이 GND로 끌려 **LOW**가 되고 버튼을 누르면 5V가 직접 연결되어 **HIGH**가 된다. 반대로 전원 쪽에 저항을 달면 풀업(Pull-up)이 되며 이 경우 누를 때 LOW가 읽힌다. 실습 회로에서는 풀다운 방식을 사용했다.

#### 2.1.3 시리얼(Serial) 통신

시리얼 통신은 데이터를 한 비트씩 순서대로 보내는 **직렬 통신**이다. 송신 측과 수신 측의 통신 속도인 **보레이트(baud rate)** 를 반드시 맞춰야 하며 맞지 않으면 글자가 깨져서 출력된다. 실습에서는 `Serial.begin(115200)`으로 115200 bps를 사용했고 시리얼 모니터를 통해 버튼 상태나 센서 값을 확인하는 디버깅 용도로 활용했다. 나중에 SBC와 MCU를 연동할 때도 이런 직렬 통신이 기본이 될 것이다.

#### 2.1.4 바운싱(Bouncing)과 디바운싱

기계식 버튼은 누르는 순간 내부 접점이 미세하게 튀면서 짧은 시간 동안 HIGH와 LOW가 여러 번 반복된다. 이를 **바운싱**이라고 하며 한 번 눌렀는데 여러 번 눌린 것처럼 인식되는 문제가 생긴다. 

이를 해결하는 것이 **디바운싱**으로 상태가 바뀐 뒤 일정 시간 기다렸다가 다시 확인하는 소프트웨어 방식과 RC 회로를 다는 하드웨어 방식이 있다. 이번 실습 코드에서는 `delay(10)`, `delay(50)`으로 읽기 간격을 두는 정도로만 처리했다. 하지만 `delay()`는 기다리는 동안 다른 작업을 모두 멈추게 하므로 `millis()`로 시간을 비교하는 방식이 더 낫다는 것을 알았다.

해결 방법: 입력값이 바뀐 시각을 기록해 두고 그 값이 50 ms 정도 바뀌지 않고 유지될 때만 실제 입력으로 인정하면 접점이 튀는 동안의 신호는 무시된다. 이렇게 하면 `loop()`가 멈추지 않아 버튼을 처리하면서도 다른 작업을 함께 수행할 수 있다.

#### 2.1.5 PWM과 듀티 사이클(Duty Cycle)

디지털 핀은 0V 아니면 5V(ESP32는 3.3V)만 낼 수 있다. **PWM(Pulse Width Modulation)** 은 이 신호를 빠르게 켜고 끄면서 한 주기 안에서 HIGH인 시간의 비율(듀티 사이클)을 조절해 평균 전압을 바꾸는 방식이다.

#### 2.1.6 ADC

ADC(Analog to Digital Converter)는 아날로그 전압을 MCU가 처리할 수 있는 숫자로 바꿔주는 장치이다. 가변저항(포텐셔미터)은 손잡이를 돌리면 가운데 단자의 전압이 0V부터 기준 전압(Uno는 5V, ESP32는 3.3V)까지 연속적으로 변한다. 이 전압을 ADC가 일정한 단계로 나누어 정수로 읽는다.

```cpp
// Arduino Uno: 0 ~ 1023 → PWM 0 ~ 255
int value = analogRead(A2);
int brightness = map(value, 0, 1023, 0, 255);
```

### 2.2 실습 수행 과정

먼저 Tinkercad에서 Arduino Uno로 회로를 구성해 시뮬레이션으로 동작을 확인한 뒤 실제 ESP32 보드에서 같은 개념을 부저와 서보모터까지 확장하는 순서로 진행했다.

#### 2.2.1 Tinkercad 실습 순서

1. 버튼은 한쪽을 5V에, 다른 쪽을 D2와 풀다운 저항(→GND)에 연결해 플로팅을 방지했다.
2. 버튼 상태에 따라 D7의 LED가 켜지도록 회로와 코드를 구성했다.
3. 가변저항은 양쪽 단자를 5V·GND에, 가운데 단자를 A2에 연결했고 LED는 PWM이 되는 D9(~ 표시 핀)에 연결했다.
4. 코드를 작성하고 시뮬레이션을 실행한 뒤 시리얼 모니터로 값을 확인했다.

#### 2.2.2 ESP32 실습 순서

1. Arduino IDE에 ESP32 보드 패키지와 `ESP32Servo` 라이브러리를 설치했다.
2. 가변저항을 GPIO39(입력 전용 ADC 핀)에 연결하고, 시리얼 모니터로 0~4095 값이 나오는지 먼저 확인했다.
3. 부저를 GPIO5에 연결하고 `ledcAttach()`로 2000 Hz, 8 bit PWM 채널을 설정했다.
4. 서보모터 신호선을 GPIO14에 연결하고, 고정 각도 → 스윕 → 가변저항 연동 순서로 단계적으로 테스트했다.

### 2.3 구현 결과 및 코드 분석

#### 2.3.1 푸시 버튼 입력 / 버튼으로 LED 제어 (디지털 입력)

```cpp
int buttonState = digitalRead(buttonPin);
if (buttonState == HIGH) {
  digitalWrite(ledPin, HIGH);
  Serial.println("Pressed");
} else {
  digitalWrite(ledPin, LOW);
  Serial.println("Not Pressed");
}
```

- **결과:** 버튼을 누르지 않으면 시리얼 모니터에 `Not Pressed`가 계속 출력되고 누르면 `Pressed`가 출력되면서 LED가 켜졌다.
- **적용 이론:** 풀다운 저항 덕분에 버튼을 떼면 항상 LOW로 읽혔다(플로팅 방지). 시리얼 통신(115200 bps)으로 입력 상태를 모니터링했고 `delay(10)`/`delay(50)`으로 읽기 간격을 두어 바운싱 영향을 줄였다.

#### 2.3.2 가변저항으로 LED 밝기 조절 (아날로그 입력 + PWM)

```cpp
int value = analogRead(potPin);               // 0 ~ 1023
int brightness = map(value, 0, 1023, 0, 255); // PWM 범위로 변환
analogWrite(ledPin, brightness);
```

- **결과:** 가변저항을 끝까지 돌리면 시리얼 모니터에 1023이 출력되고 LED가 가장 밝게 켜졌다. 반대로 돌리면 점점 어두워졌다.
- **적용 이론:** 10 bit ADC 값(0~1023)을 `map()`으로 8 bit PWM 값(0~255)으로 변환했다. `analogWrite()`는 실제 아날로그 전압이 아니라 **듀티 사이클을 바꾸는 PWM**이기 때문에 ~ 표시가 있는 D9 핀을 사용해야 했다.

#### 2.3.3 ESP32 가변저항 값 읽기

- **결과:** GPIO39에서 읽은 값이 0~4095 범위로 출력되었다.
- **적용 이론:** ESP32의 ADC는 12 bit라 Uno(10 bit)보다 4배 더 세밀하다. 같은 코드라도 보드에 따라 값의 범위가 다르다는 것을 확인했다.

#### 2.3.4 ESP32 부저 (LEDC PWM)

```cpp
ledcAttach(BUZZER_PIN, 2000, 8);  // 2000 Hz, 8 bit(0~255)
ledcWrite(BUZZER_PIN, 32);   // 듀티 약 12.5%
ledcWrite(BUZZER_PIN, 64);   // 약 25%
ledcWrite(BUZZER_PIN, 128);  // 약 50%
ledcWrite(BUZZER_PIN, 0);    // 꺼짐
```

- **결과:** 2000 Hz 음이 1초씩 작은 소리 -> 중간 -> 큰 소리 -> 무음 순서로 반복되었다.
- **적용 이론:** **주파수는 음의 높이**를 **듀티 사이클은 소리의 크기**를 결정한다. ESP32는 `analogWrite` 대신 LEDC 하드웨어 PWM을 쓰며 주파수와 해상도를 직접 지정할 수 있다. 듀티 50%(128)일 때 가장 크게 들렸다.

#### 2.3.5 ESP32 서보모터 (왕복 / 스윕 / 가변저항 연동)

```cpp
// 스윕: 1도씩 15 ms 간격으로 이동
for (pos = 0; pos <= 180; pos += 1) { myServo.write(pos); delay(15); }

// 가변저항 연동
int value = analogRead(POT_PIN);          // 0 ~ 4095
int angle = map(value, 0, 4095, 0, 180);  // 각도로 변환
myServo.write(angle);
```

- **결과:** 1. 0°↔180°를 1초마다 빠르게 왕복 2. 스윕은 한 방향 약 2.7초(181단계 × 15 ms)에 걸쳐 부드럽게 이동 3. 가변저항을 돌리는 대로 서보 각도가 따라왔다.
- **적용 이론:** 서보모터는 약 50 Hz PWM 신호의 **펄스 폭**으로 각도를 결정한다. `ESP32Servo` 라이브러리가 각도를 펄스 폭으로 바꿔주기 때문에 `write(각도)`만 호출하면 된다. 입력(센서) → 변환(map) → 출력(액추에이터)으로 이어지는 저수준 제어의 기본 구조 실습이었다.

## 3. 느낀 점

- **풀다운의 필요성:** 저항 하나로 입력이 안정되는 것을 보며 하드웨어 회로 설계가 소프트웨어만큼 중요하다는 것을 느꼈다.
- **디바운싱 보완:** 이번 코드는 `delay()`로만 간격을 두었는데, `delay()`는 그동안 다른 작업을 모두 멈추게 한다. 로봇처럼 여러 작업을 동시에 해야 하는 경우에는 `millis()`로 시간을 비교하는 논블로킹 디바운싱이 더 적합할 것 같다.
- **보드 간 차이:** 같은 가변저항이라도 Uno는 0~1023, ESP32는 0~4095 범위로 읽혔다. 그래서 Uno용 `map(value, 0, 1023, ...)` 코드를 ESP32에 그대로 쓰면 가변저항을 1/4만 돌려도 최댓값에 도달하는 문제가 생긴다. PWM 출력 함수도 Uno는 `analogWrite`, ESP32는 `ledcAttach`/`ledcWrite`로 달랐다. 따라서 코드를 다른 보드로 옮길 때는 ADC 해상도와 사용하는 함수를 꼭 확인해야 한다.
- **PWM의 활용 범위:** LED 밝기, 부저 음량, 서보 각도가 모두 PWM 하나의 원리로 제어된다는 점이 인상 깊었다.
- **시뮬레이션 → 실물 순서:** Tinkercad에서 먼저 검증하고 실제 보드로 넘어가니 회로 실수로 부품을 망가뜨릴 위험을 줄일 수 있어서 좋았다.
